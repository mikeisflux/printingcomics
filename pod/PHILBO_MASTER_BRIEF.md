# 13. PHILBO ID

PHILBO ID is system-generated.

Formula:

`NORMALIZED SERIES CODE + "-" + LAST FIVE DIGITS OF UPC`

Example:

- Series Code: `GHSTHNT`
- UPC: `74470025881002`
- PHILBO ID: `GHSTHNT-81002`

Rules:

- Series Code required
- UPC required
- Remove spaces from Series Code
- Convert Series Code to uppercase
- Prevent duplicates
- Read-only for publishers
- Admin override only when necessary
- Do not include FOC or release date
- PHILBO ID may update while Draft
- After Approved or Live, changes require Admin approval
- Use PHILBO ID across catalog, files, inventory, orders, Purchase Orders, Production Orders, returns, payouts, and reports

# 20. RETAILER CATALOG CSV EXPORT

Each Catalog Cycle generates a retailer-facing master CSV from the same Live title records used by the storefront.

Retailers may download:

- Current Catalog CSV
- Upcoming Catalog CSV
- Archived Catalog CSVs

Only approved logged-in retailers may download retailer CSVs.

The CSV should include retailer-relevant title fields and:

- PHILBO ID
- MSRP
- The logged-in retailer’s wholesale price
- The logged-in retailer’s tier
- Ordering status
- FOC lock status
- Downloadable cover image URL

Do not expose all tier prices in a retailer download.

Admin and Super Admin may access an Admin export with all tier pricing.

Suggested filename:

`Philbo_Catalog_2026-10_FOC_2026-12-01.csv`

The CSV should regenerate when:

- A title becomes Live
- A live title changes
- A title is removed
- A title changes cycles
- FOC status changes
- Retail pricing rules change
- Cover image URL changes

The storefront and retailer CSV must use the same source records.

## Retailer CSV ordering

The catalog-data CSV and CSV ordering are separate functions.

- **Catalog Data** is the complete monthly catalog export created from approved title records.
- **Order Form** is a retailer-specific CSV containing orderable products, the retailer's wholesale price, and a blank `Qty` column.
- A retailer downloads the Order Form, enters quantities, saves it as CSV, and uploads it from the retailer ordering workspace.
- The upload must match each row by PHILBO ID, UPC, ISBN, or EAN and validate quantities, duplicates, unknown codes, and FOC locks.
- Uploading does not submit an order. Valid lines are added to Current Order, where the retailer reviews quantities, pricing, and totals before final submission.
- Invalid rows remain visible and are never silently discarded.
